// 01 — יסודות

מה זה Active Directory?

הבנה מלאה של המושג, ההיסטוריה והחשיבות של Active Directory בעולם ה-IT הארגוני.

🎯 ההגדרה הפשוטה

Active Directory (AD) הוא שירות ספרייה (Directory Service) שפיתחה Microsoft. תחשוב עליו כמו "ספר הטלפונים הארגוני האולטימטיבי" — אבל הרבה יותר חזק. הוא מנהל את כל הזהויות, ההרשאות, המדיניות והמשאבים בארגון.


כל פעם שאתה נכנס לעבודה ומזין שם משתמש וסיסמה — AD הוא זה שבודק אותך. כל פעם שאתה ניגש לשרת קובץ, מדפסת, או אפליקציה — AD הוא זה שמחליט אם מותר לך.

📅 היסטוריה קצרה

1999
Windows 2000 Server
השקת AD הראשונה, מבוסס על X.500 ו-LDAP
2003
Forests & Trusts
הכנסת יערות, אמונות בין דומיינים
2008
AD DS, AD FS, AD CS
הרחבת לשירותים נוספים: Federation, Certificate
2016+
Azure AD / Entra ID
גרסת הענן, היברידיות עם On-Prem

💡 למה כל ארגון צריך AD?

דמיין ארגון עם 500 עובדים ו-50 שרתים. בלי AD:

  • כל שרת יצטרך לנהל את רשימת המשתמשים שלו בנפרד — זה 500 × 50 = 25,000 חשבונות!
  • כל שינוי סיסמה יצטרך לעדכן בכל מקום ידנית
  • לא ניתן לאכוף מדיניות אחידה על תחנות עבודה
  • אבטחה — בלתי אפשרית לנהל

עם AD: משתמש אחד, סיסמה אחת, הרשאות מרכזיות, מדיניות אחידה — כל זה מנוהל ממקום אחד.

🏗️ רכיבי AD המרכזיים

  • AD DS — Directory Services (הליבה)
  • AD CS — Certificate Services (PKI)
  • AD FS — Federation Services (SSO)
  • AD LDS — Lightweight Directory Services
  • AD RMS — Rights Management Services

🌲 Forest (יער)

הגבול האבטחתי הגבוה ביותר ב-AD. יכיל עץ דומיין אחד או יותר. כל אובייקטים ביער חולקים:

  • Schema אחד משותף
  • Configuration Container אחד
  • Global Catalog מאוחד
  • Trust אוטומטי בין דומיינים ביער

🔷 Domain (דומיין)

יחידת ניהול ואבטחה בסיסית. כל דומיין מכיל:

  • Domain Controllers (DC) — שרתי האימות
  • Database AD — NTDS.dit
  • הגדרות מדיניות Group Policy
  • Trusts עם דומיינים אחרים

📁 Organizational Unit (OU)

מיכל לוגי לארגון אובייקטים בתוך דומיין. OU מאפשר:

  • הפעלת GPO ספציפי על קבוצת אובייקטים
  • האצלת הרשאות ניהול (Delegation)
  • מבנה היררכי — OU תוך OU
  • ניהול נוח: IT \ סיסטמאים \ Junior

🖥️ Sites (אתרים פיזיים)

הירארכיה פיזית של AD, מבוססת על טופולוגיית הרשת:

  • Site — רשת IP מחוברת היטב (LAN)
  • Site Link — חיבור WAN בין אתרים
  • משמש לשליטה על תעבורת רפליקציה
  • משפיע על איזה DC המשתמש מתחבר

🏆 FSMO Roles — תפקידים בודדים בדומיין

חמישה תפקידים ייחודיים שחייבים להיות על DC אחד בלבד:

Forest-wide (כל יער):
  • Schema Master — שולט בשינויי ה-Schema
  • Domain Naming Master — מנהל הוספת/הסרת דומיינים
Domain-wide (כל דומיין):
  • PDC Emulator — שעון, נעילות, עדכוני סיסמה
  • RID Master — מחלק מזהי RID לאובייקטים
  • Infrastructure Master — מעדכן הפניות בין דומיינים
# בדיקת FSMO Roles:
netdom query fsmo

Schema master DC01.corp.example.com
Domain naming master DC01.corp.example.com
PDC DC01.corp.example.com
RID pool manager DC01.corp.example.com
Infrastructure master DC02.corp.example.com

# או PowerShell:
Get-ADDomain | Select-Object *Master, PDCEmulator
Get-ADForest | Select-Object *Master

📦 Global Catalog (GC)

שרת מיוחד המכיל עותק חלקי של כל אובייקטי היער (לא רק הדומיין שלו). חיוני ל:

  • חיפוש משתמשים ומשאבים בכל היער
  • כניסת לוגון — אימות חברות בקבוצות Universal
  • שירות Exchange (הכתובות נשמרות ב-GC)
  • גש דרך Port 3268 (LDAP) או 3269 (LDAPS)
// 03 — פרוטוקולים

פרוטוקולים בסביבת Active Directory

כל הפרוטוקולים שמריצים את AD — מ-Kerberos ועד DNS

פרוטוקול יציאה סוג שימוש ב-AD
Kerberos 88 TCP/UDP אימות ראשי — מנגנון tickets
LDAP 389 TCP/UDP גישה וחיפוש בספרייה
LDAPS 636 TCP LDAP מוצפן (SSL/TLS)
DNS 53 TCP/UDP מיפוי שמות, מציאת DCs (SRV records)
SMB / CIFS 445 TCP שיתוף קבצים, SYSVOL, NETLOGON
RPC 135 + דינמי TCP תקשורת בין DCs, ניהול מרחוק
NTLM מגוון TCP/UDP אימות legacy (פחות מומלץ)
Global Catalog 3268 / 3269 TCP חיפוש ביער שלם
NTP / W32TM 123 UDP סנכרון שעון — קריטי ל-Kerberos!
WinRM / WMI 5985/5986 TCP ניהול מרחוק, PowerShell Remoting

🎟️ Kerberos — איך זה עובד?

Kerberos הוא פרוטוקול אימות מבוסס Tickets. הוא פועל בשלבים:


1. AS-REQ — הלקוח שולח בקשת אימות ל-KDC
2. AS-REP — KDC מחזיר TGT (Ticket Granting Ticket)
3. TGS-REQ — הלקוח מבקש Service Ticket
4. TGS-REP — KDC מחזיר Service Ticket
5. AP-REQ — הלקוח מתחבר לשירות עם הטיקט
6. AP-REP — השירות מאשר את הזהות

⚠️ קריטי: כל המחשבים חייבים להיות מסונכרנים בזמן — סטייה של יותר מ-5 דקות = כישלון אימות!

⚠️ NTLM — הפרוטוקול הישן

NTLM הוא מנגנון האימות הישן שעדיין קיים ל-backwards compatibility:

  • משתמש ב-Challenge/Response
  • אין Mutual Authentication (חולשה!)
  • פגיע ל-Pass-the-Hash, Relay attacks
  • מופעל כאשר Kerberos נכשל
  • מומלץ להגביל ל-NTLMv2 לפחות

✅ מומלץ: להגביל NTLM ולהשתמש רק ב-Kerberos כשאפשר

📡 DNS — הבסיס של AD

AD תלוי ב-DNS לחלוטין. ה-DNS מכיל:

  • SRV Records — מציאת DCs, GCs, Kerberos
  • A Records — שמות לכתובות IP
  • _ldap._tcp.corp.example.com — מציאת DC
  • _kerberos._tcp.corp.example.com — KDC

🔄 Intra-Site Replication (תוך-אתר)

  • מהיר: שינוי מתפשט תוך 15 שניות
  • לא מכווץ (רשת מהירה)
  • KCC (Knowledge Consistency Checker) בונה Ring Topology
  • שינויים נשלחים מיד (Urgent Replication לאירועים קריטיים)
  • Urgent: נעילת חשבון, שינוי סיסמה, LSA Policy

🌐 Inter-Site Replication (בין-אתרים)

  • מתוזמן — ברירת מחדל כל 180 דקות
  • מכווץ — חוסך bandwidth
  • דרך Site Links ו-Bridgehead Servers
  • ISTG בוחר Bridgehead Server אוטומטית
  • ניתן לתזמן ולכוון את החלונות

📊 USN — Update Sequence Numbers

כל שינוי ב-AD מקבל USN (Update Sequence Number) — מספר עולה. כך DC יודע מה כבר קיבל ומה עדיין חסר:

  • כל DC שומר UTD Vector — מה ה-USN הגבוה שקיבל מכל DC
  • בעת רפליקציה: "תן לי הכל מ-USN 5432 ואילך"
  • Originating USN vs Local USN — חשוב להבדיל
  • Attribute Metadata — כולל מי שינה, מתי, ומה ה-USN

⚠️ Replication Conflicts — מה קורה כשיש סתירה?

שני DCs ביצעו שינוי על אותו אובייקט לפני שהרפליקציה התרחשה:

  • Last Writer Wins — השינוי עם ה-Timestamp המאוחר יותר ינצח
  • Attribute-level conflict resolution — לא אובייקט שלם!
  • Object Deletion conflict: שינוי vs מחיקה — המחיקה ניצחת
  • Tombstone — אובייקט מחוק נשמר 60-180 יום לפני שנמחק לצמיתות
# בדיקת סטטוס רפליקציה:
repadmin /showrepl
repadmin /replsummary
repadmin /showutdvec DC01 dc=corp,dc=example,dc=com

# כפיית רפליקציה:
repadmin /syncall /AdeP
repadmin /replicate DC02 DC01 "dc=corp,dc=example,dc=com"

# בדיקת שגיאות רפליקציה:
Get-ADReplicationFailure -Scope Forest
Get-ADReplicationPartnerMetadata -Target DC01
// 05 — חשבונות

חשבונות ב-Active Directory

משתמשים, קבוצות, מחשבים, Service Accounts וכל מה שביניהם

👤 User Account Attributes

  • sAMAccountName — שם משתמש (max 20 תווים)
  • userPrincipalName — UPN (david@corp.com)
  • distinguishedName — נתיב מלא ב-LDAP
  • objectGUID — מזהה ייחודי גלובלי
  • objectSID — Security Identifier
  • memberOf — קבוצות שהמשתמש חבר
  • pwdLastSet — תאריך שינוי סיסמה
  • lastLogon — כניסה אחרונה
  • accountExpires — תפוגת חשבון

🔐 מדיניות סיסמאות

שני סוגים:


Default Domain Password Policy:
  • מדיניות ברמת דומיין (GPO)
  • חלה על כולם — כל המשתמשים
  • אורך מינימלי, מורכבות, היסטוריה

Fine-Grained Password Policy (PSO):
  • מדיניות שונה לקבוצות שונות
  • Admin יכול לדרוש סיסמה חזקה יותר
  • ניהול דרך ADAC או PowerShell
# יצירת משתמש:
New-ADUser -Name "David Cohen" -SamAccountName "david.cohen" `
-UserPrincipalName "david.cohen@corp.example.com" `
-Path "OU=IT,DC=corp,DC=example,DC=com" `
-AccountPassword (ConvertTo-SecureString "P@ssw0rd!" -AsPlainText -Force) `
-Enabled $true

# חיפוש משתמשים לא פעילים:
Search-ADAccount -AccountInactive -TimeSpan 90.00:00:00 -UsersOnly

# נעילת / שחרור חשבון:
Unlock-ADAccount -Identity david.cohen

👥 סוגי קבוצות — Group Types


Security Groups:

לניהול הרשאות גישה למשאבים


Distribution Groups:

לשליחת אימייל בלבד (Exchange), אין שימוש אבטחתי

🎯 Scope — טווח הקבוצה

  • Domain Local — הרשאה למשאב בדומיין, חברות מכל מקום
  • Global — ארגון משתמשים, גישה לכל מקום ביער
  • Universal — ביער שלם, נשמר ב-GC (attention: GC traffic)

Best Practice: AGDLP

Accounts → Global Groups → Domain Local Groups → Permissions

🏆 Built-in Groups חשובים

  • Domain Admins — מנהלי דומיין מלאים
  • Enterprise Admins — מנהלי יער
  • Schema Admins — שינוי Schema
  • Administrators — ניהול DC
  • Account Operators — ניהול חשבונות
  • Backup Operators — גיבוי/שחזור
  • Remote Desktop Users — כניסה מרחוק
  • Protected Users — אבטחה מוגברת

💻 Computer Account

כל מחשב שמוצמד לדומיין מקבל חשבון משלו ב-AD. זה מאפשר:

  • אימות המחשב עצמו (לא רק המשתמש)
  • הפעלת GPO על המחשב
  • כניסה ללא רשת (Cached Credentials)
  • Kerberos — המחשב מקבל TGT משלו

Machine Account Password: מתחדש כל 30 יום אוטומטית

🔗 Domain Join

תהליך הצמדת מחשב לדומיין:

  • 1. DNS — מציאת DC
  • 2. Netlogon — אימות
  • 3. יצירת Computer Account ב-AD
  • 4. יצירת Secure Channel
  • 5. הורדת GPOs
  • 6. רישום SPN
# הצמדה לדומיין:
Add-Computer -DomainName "corp.example.com" -Credential (Get-Credential) -Restart

# בדיקת Secure Channel:
Test-ComputerSecureChannel
Repair-ComputerSecureChannel # תיקון אם שבור

⚙️ Service Accounts

שלושה סוגי חשבונות שירות:


רגיל (User Account ישן):
  • בעיות: סיסמה לא מתחדשת, SPN conflicts

MSA (Managed Service Account):
  • סיסמה אוטומטית (120 תווים, כל 30 יום)
  • מחובר למחשב אחד בלבד
  • Windows 2008 R2+

gMSA (Group Managed Service Account):
  • כמו MSA אבל לכמה שרתים
  • אידיאלי ל-NLB, Web Farms
  • KDS Root Key נדרש

🎫 SPN — Service Principal Name

מזהה ייחודי של שירות ב-Kerberos. פורמט:

serviceClass/host:port/serviceName
HTTP/webserver.corp.com:80
MSSQLSvc/sql01.corp.com:1433
HOST/workstation01.corp.com

SPN כפול = בעיית Kerberos!


setspn -L username
setspn -X # מציאת כפילויות
// 06 — אבטחה

אבטחה ב-Active Directory

GPO, Tiered Administration, כלי ניטור ותקיפות נפוצות

📋 Group Policy Object (GPO)

GPO מאפשר לאכוף הגדרות על משתמשים ומחשבים:

  • Computer Configuration — חל בעת אתחול
  • User Configuration — חל בעת כניסה
  • מוחל לפי: Local → Site → Domain → OU
  • מנגנון RSAT: gpmc.msc לניהול
  • Inheritance, Block, Enforce (לוחץ מלמעלה)

דוגמאות שימוש: הגדרת Firewall, מניעת USB, מיפוי כוננים, הגדרת IE, הפצת תוכנות

🏛️ Tiered Administration Model

מודל שלוש שכבות להגנה על חשבונות הכי חשובים:


🔴 TIER 0 — Domain/Enterprise Admins, DC, Schema
↕ אין אינטראקציה
🟡 TIER 1 — שרתי אפליקציה, DBAs, Admins
↕ אין אינטראקציה
🟢 TIER 2 — Workstations, Help Desk, Users

🛡️ Privileged Access Workstation (PAW)

  • מחשב ייעודי לניהול פריבילג'ים
  • מנותק מהאינטרנט / דוא"ל
  • hardened — Windows Credential Guard
  • רק מ-PAW ניתן לנהל Tier 0
  • Just-in-Time (JIT) Access

🔍 ACL — Access Control Lists

  • DACL — מי יכול לעשות מה
  • SACL — מה מוקלט ב-Audit Log
  • ACE — רשומה בודדת ב-ACL
  • ירושה מ-OU לאובייקטים בתוכה
  • כלי: dsacls, ADExplorer, ADSI Edit

⚠️ תקיפות נפוצות על AD — מה צריך להגן?

  • Pass-the-Hash — שימוש ב-NTLM Hash ישיר
  • Pass-the-Ticket — גנבת Kerberos TGT
  • Golden Ticket — זיוף TGT עם KRBTGT hash
  • Silver Ticket — זיוף Service Ticket
  • Kerberoasting — פיצוח SPN tickets
  • DCSync — חיקוי DC לשליפת הכל
  • AS-REP Roasting — ללא Pre-Auth
  • BloodHound — מיפוי נתיבי תקיפה
  • LDAP Enumeration — איסוף מידע
  • AdminSDHolder — persistence

הגנה: Credential Guard, Protected Users Group, ATA/Defender for Identity, כיבוי NTLM, monitoring DCSync

✅ Hardening Checklist

  • ✅ Protected Users Group — לכל admin
  • ✅ KRBTGT password reset — כל 6 חודשים
  • ✅ Local Administrator Password Solution (LAPS)
  • ✅ Disable LLMNR, NBT-NS (MITM prevention)
  • ✅ SMB Signing Enabled
  • ✅ Restrict NTLMv1, prefer NTLMv2 → Kerberos
  • ✅ Enable Audit Logging (4624, 4625, 4648, 4776)
  • ✅ Domain Controller Firewall
  • ✅ Disable pre-authentication required = $false
  • ✅ AdminSDHolder — monitor changes
// 07 — Sessions

User Sessions ותהליך הכניסה

מה קורה מרגע הקשת הסיסמה ועד לשולחן העבודה

🔄 תהליך Logon מלא (Domain Logon)

1. המשתמש מקיש Ctrl+Alt+Del ומזין credentials
2. Winlogon → LSA (Local Security Authority) מקבל את הנתונים
3. LSA → Kerberos (או NTLM) מנסה לאמת מול DC
4. DC → KDC מחזיר TGT (Ticket Granting Ticket)
5. TGT נשמר ב-LSASS process memory (כאן מתרחש Pass-the-Ticket!)
6. DC מחזיר Access Token עם SIDs של המשתמש וקבוצותיו
7. הורדת Group Policy (Startup/Logon Scripts)
8. טעינת פרופיל (Roaming Profile אם מוגדר)
9. שולחן העבודה מופיע — Explorer.exe עולה עם ה-Token

🎫 Access Token

האסימון שמייצג את זהות המשתמש בתוך Windows:

  • User SID
  • Group SIDs (כולל Domain Local, Global, Universal)
  • Privileges (SeDebugPrivilege, etc.)
  • Integrity Level (Low/Medium/High/System)
  • Logon Session ID
  • Source (Network, Interactive, Service)

🏠 User Profiles

  • Local Profile — שמור על המחשב המקומי בלבד
  • Roaming Profile — נשמר על שרת, נטען בכל כניסה
  • Mandatory Profile — פרופיל קבוע שלא נשמר
  • Folder Redirection — Desktop/Documents → שרת
  • מיקום: \\server\profiles\%username%

🔐 Credential Types ב-LSASS

  • Kerberos Tickets (TGT + Service Tickets)
  • NTLM Hashes — NTHash בזיכרון
  • Plaintext Passwords — ב-WDigest (ישן!)
  • DPAPI keys — הצפנת credentials
  • Mimikatz — כלי שמחלץ הכל מ-LSASS

⏰ Session Types

  • Interactive — כניסה פיזית/RDP
  • Network — גישה למשאב רשת
  • Batch — Task Scheduler
  • Service — שירות Windows
  • RemoteInteractive — RDP
  • NetworkCleartext — IIS Basic Auth

🛡️ Credential Guard

תכונת Windows 10/11 שמגינה על LSASS באמצעות Virtualization-Based Security (VBS):

  • Credentials מוגנים ב-Isolated LSA Process (VSM)
  • Mimikatz לא יכול לחלץ Kerberos tickets מהזיכרון
  • דורש UEFI Secure Boot + Hyper-V
  • הפעלה: GPO → Device Guard → Enable Virtualization Based Security
# ניטור Sessions:
qwinsta /server:DC01 # הצגת sessions על שרת
query session # sessions מקומיות
logoff [session_id] # ניתוק session

# Event IDs חשובים לניטור:
# 4624 - Successful Logon
# 4625 - Failed Logon
# 4634/4647 - Logoff
# 4648 - Logon with explicit credentials

// 08 — SCCM

SCCM — System Center Configuration Manager

ניהול תשתית מרכזי — תוכנות, עדכונים, inventory, ועוד

📦 מה זה SCCM / Endpoint Config Manager?

SCCM (כיום: Microsoft Endpoint Configuration Manager או MECM) הוא פלטפורמת ניהול ארגונית שמשלימה את AD. בעוד AD מנהל זהויות, SCCM מנהל מכשירים ואפליקציות.


SCCM משתלב עמוק עם AD לצורך גילוי מחשבים, ניהול קולקציות ואכיפת תצורה.

🏗️ רכיבי SCCM

  • Site Server — שרת ה-SCCM הראשי
  • Site Database — SQL Server, מאגר הנתונים
  • Distribution Point (DP) — חלוקת תוכן
  • Management Point (MP) — תקשורת עם Clients
  • Software Update Point (SUP) — WSUS integration
  • Reporting Services Point — דוחות SSRS
  • SCCM Client — Agent על כל מחשב
📤

Software Distribution

הפצת אפליקציות ל-Collections. תמיכה ב-MSI, Script, App-V. Deployment Types, Dependencies, Supersedence.

🔄

Software Updates

ניהול Windows Updates דרך WSUS. ADR (Auto Deployment Rules) לעדכונים אוטומטיים. Maintenance Windows.

🖥️

OS Deployment (OSD)

הפצת תמונת Windows דרך Task Sequence. PXE Boot, MDT Integration. Zero-touch deployment.

📊

Hardware/Software Inventory

איסוף מידע על חומרה ותוכנה. WMI-based. ניתן להוסיף Custom Classes. Compliance Reporting.

⚙️

Compliance Settings (DCM)

Configuration Baselines — בדיקת תצורה ואכיפתה. Remediation אוטומטי. CIS Benchmarks.

🔒

Endpoint Protection

ניהול Microsoft Defender Antivirus, Windows Firewall. Anti-malware policies. Integration עם Security Center.

🔗 SCCM + AD Integration

  • Active Directory Discovery — SCCM מגלה משתמשים, קבוצות, מחשבים מ-AD
  • AD-based Collections — קולקציה מבוססת OU או Security Group
  • AD Site Boundaries — שימוש ב-AD Sites לגבולות SCCM
  • Group Policy — הפצת SCCM Client דרך GPO
  • Client Authentication דרך PKI / AD Certificates

// 09 — ניטור מתקדם

ATA — Advanced Threat Analytics

גילוי איומים מתקדמים בסביבת AD — ו-Microsoft Defender for Identity (הגרסה החדשה)

🔍 מה זה ATA?

Microsoft Advanced Threat Analytics (ATA) היה כלי On-Premise לגילוי תקיפות מתקדמות ב-AD. כיום הוחלף על ידי Microsoft Defender for Identity (MDI) — גרסת הענן.


שניהם עובדים ע"י:

  • Port Mirroring מה-DC
  • ניתוח תעבורת Kerberos, DNS, NTLM
  • Machine Learning לזיהוי אנומליות
  • Behavioral analytics (Baseline)

🎯 איומים שATA/MDI מזהה

  • 🔴 Pass-the-Ticket — שימוש ב-TGT גנוב
  • 🔴 Pass-the-Hash — NTLM Hash שימוש חוזר
  • 🔴 Golden Ticket — זיוף Kerberos
  • 🔴 DCSync Attack — שכפול DC
  • 🟡 Reconnaissance — סריקת AD
  • 🟡 Kerberoasting
  • 🟡 Brute Force על Kerberos/NTLM
  • 🟡 Lateral Movement
  • 🟢 Sensitive Groups Changes

🚀 Microsoft Defender for Identity (MDI)

הגרסה החדשה, מבוססת ענן (Sentinel/Defender XDR):

  • Sensor מותקן על DC (לא Gateway נפרד)
  • Cloud-powered analytics
  • Integration עם Microsoft 365 Defender
  • UEBA — User and Entity Behavior Analytics
  • Honeytokens — חשבונות מלכודת
  • Integration עם SIEM (Sentinel)
  • Timeline — ניתוח נתיב תקיפה

🔌 התקנת MDI Sensor

  • הורד MDI Sensor מ-Portal
  • התקן על כל Domain Controller
  • הגדר Directory Services Account (DSA)
  • DSA צריך: Read אובייקטים ב-AD
  • לא צריך Admin! (Principle of Least Privilege)
  • Sensor שולח נתונים ל-MDI Cloud

🔎 Event Forwarding לאבטחה

Event IDs שצריך לאסוף:

  • 4662 — שינויים על אובייקטים AD
  • 4688 — Process Creation
  • 4768/4769 — Kerberos Tickets
  • 4776 — NTLM Auth
  • 7045 — שירות חדש (persistence!)
  • Windows Event Forwarding (WEF) → SIEM
// 10 — תרגול מעשי

מעבדה — Hands-On

תרגולים מעשיים שיעזרו לך להבין AD מבפנים

1
הקמת Lab בסיסי — DC ו-Client
קל
  • הורד Hyper-V / VMware Workstation. צור שני VMs: Windows Server 2022 (DC) + Windows 11 (Client)
  • על ה-VM שיהיה DC: הגדר IP סטטי (192.168.1.10), DNS מצביע לעצמו (127.0.0.1)
  • התקן תפקיד AD DS: Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
  • קדם ל-DC: Install-ADDSForest -DomainName "lab.local" -SafeModeAdministratorPassword (Read-Host -AsSecureString)
  • לאחר Restart — הצמד את ה-Windows 11 VM לדומיין lab.local. אמת שאתה יכול להיכנס עם חשבון דומיין
2
יצירת מבנה OU ומשתמשים
קל
  • פתח ADUC (dsa.msc) וצור OU structure: IT \ Admins, IT \ Helpdesk, HR, Finance
  • צור 5 משתמשים בכל OU. השתמש ב-PowerShell:
    1..5 | ForEach { New-ADUser -Name "IT User $_" -SamAccountName "it.user$_" -Path "OU=IT,DC=lab,DC=local" -Enabled $true -AccountPassword (ConvertTo-SecureString "Lab@2024!" -AsPlainText -Force) }
  • צור Security Groups ב-IT OU: IT-Admins, Helpdesk-Team. הוסף משתמשים לקבוצות המתאימות
  • אמת חברות בקבוצות: Get-ADGroupMember -Identity "IT-Admins" | Select Name
3
יצירת GPO ואכיפתו
בינוני
  • פתח GPMC (gpmc.msc). צור GPO חדש: "IT Workstations Policy" וקשר אותו ל-OU IT
  • ערוך את ה-GPO: Computer Config → Policies → Windows Settings → Security Settings → Account Policies: הגדר Password Length = 12, Lockout = 5 נסיונות
  • User Config → Policies → Administrative Templates → Control Panel → Prohibit access to Control Panel = Enabled
  • על ה-Client VM: gpupdate /force ואמת שהגדרות הופעלו: gpresult /H c:\gp-report.html
4
ניתוח Replication ואיתור שגיאות
בינוני
  • הוסף DC שני לדומיין. צור שני VMs נוספים, התקן AD DS על השני, הצרף לדומיין הקיים
  • בדוק Replication: repadmin /showrepl, repadmin /replsummary
  • שנה משתמש על DC1 ואמת שהשינוי מופיע על DC2: Get-ADUser -Server DC2 it.user1 -Properties *
  • בדוק Sites: אתר Sites and Services (dssite.msc). אמת שה-DCs נמצאים ב-Default-First-Site-Name. הפעל כפיית רפליקציה: repadmin /syncall /AdeP
5
אבטחה — LAPS ו-Protected Users
בינוני
  • הורד והתקן LAPS (Local Administrator Password Solution) על ה-DC. הרחב את ה-Schema: Update-LapsADSchema
  • הגדר הרשאות על OU: Set-LapsADComputerSelfPermission -Identity "OU=IT,DC=lab,DC=local"
  • פרוס LAPS Client דרך GPO לכל מחשבי ה-IT. אמת קבלת סיסמה: Get-LapsADPassword -Identity WORKSTATION01
  • הוסף את חשבון Administrator שלך ל-Protected Users Group ובדוק שאתה לא יכול לבצע Pass-the-Hash
6
BloodHound — מיפוי הסביבה
מתקדם
  • הורד BloodHound + Neo4j. התקן על מחשב נפרד. הפעל Neo4j ואז BloodHound
  • הרץ את SharpHound (collector) על ה-Client: .\SharpHound.exe -c All — ייצור ZIP של הנתונים
  • העלה את ה-ZIP ל-BloodHound. שחק עם שאילתות: "Find Shortest Paths to Domain Admins", "Find AS-REP Roastable Users"
  • זהה בעיות אבטחה בסביבת ה-Lab ותקן אותן. זו הנקודה — להבין כיצד תוקף רואה את הרשת שלך

מילון AD

כל המונחים והקיצורים חשובים במקום אחד

AD DS
Active Directory Domain Services — שירות הספרייה הראשי
DC
Domain Controller — שרת שמריץ AD DS ומבצע אימות
RODC
Read-Only Domain Controller — DC לאתרים מרוחקים, ללא כתיבה
GC
Global Catalog — שרת עם עותק חלקי של כל אובייקטי היער
GPO
Group Policy Object — אובייקט מדיניות קבוצתית
OU
Organizational Unit — מיכל לוגי לאובייקטים בדומיין
SID
Security Identifier — מזהה אבטחה ייחודי לכל אובייקט
GUID
Globally Unique Identifier — מזהה 128-bit ייחודי גלובלי
UPN
User Principal Name — user@domain.com
SPN
Service Principal Name — מזהה שירות ב-Kerberos
TGT
Ticket Granting Ticket — כרטיס Kerberos ראשוני
KDC
Key Distribution Center — רכיב Kerberos על ה-DC
LDAP
Lightweight Directory Access Protocol — פרוטוקול גישה לספרייה
USN
Update Sequence Number — מספר רץ לכל שינוי ב-AD
KCC
Knowledge Consistency Checker — בונה טופולוגיית רפליקציה
ACL
Access Control List — רשימת הרשאות גישה
DACL
Discretionary ACL — מי מורשה לגשת למשאב
SACL
System ACL — מה מוקלט ב-Audit Log
PAM
Privileged Access Management — ניהול גישה פריבילג'ית
LAPS
Local Administrator Password Solution — סיסמאות admin מקומיות ייחודיות
PSO
Password Settings Object — מדיניות סיסמאות עדינה
MSA / gMSA
Managed Service Account — חשבון שירות עם סיסמה אוטומטית
RID
Relative Identifier — חלק מה-SID שמזהה אובייקט בדומיין
SYSVOL
תיקיה משותפת על DCs המכילה GPOs ו-scripts
